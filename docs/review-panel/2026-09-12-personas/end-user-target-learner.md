# End-User / Target Learner (re-aimed persona) — Review of `docs/workshop-design.md`

**Deliberate adaptation note:** the canonical version of this persona is "an advanced practitioner already using agents daily." For this run, re-aimed to this workshop's real advertised audience — a non-technical knowledge worker with an enterprise M365 Copilot seat, no git/CLI comfort assumed. This is the first workshop this factory has built for a non-engineering audience, so this lens is unusually load-bearing this run.

**Top finding — I can't find Module 1's front door.** §3 says "the published site is the primary learner surface," but the actual site build is "Phase 4's deliverable... not this design doc's." There's no description anywhere of what I'd see landing on the GitHub-hosted site, how I'd know where Module 1 starts, or — critically — how the fixture files (the firm-overview doc, Molly's portfolio) actually get into my own OneDrive/Word so Copilot can ground on them. That upload/setup step is the single most likely place I'd bounce, and it's silently absent (fair, per §13 it's "a separate run," but it means I genuinely could not start today from this doc alone).

**§11 preflight is written for IT, not me.** Terms like "SKU," "admin policy," "Notebooks feature enabled," "Analyst agent access," "Agent Store approval... may require admin approval" assume I can independently diagnose tenant configuration. I can't tell if scheduling is "disabled by admin policy" — I'd just see a missing button and have no idea why. Worse, the doc admits it itself: for Module 08, "a genuinely blocked learner needs a named 'describe what you would configure' fallback, TBD at content time" — meaning if I hit that wall today, there's nothing for me to do but quit. And the maintainer note "no file... establishes that coderturtle currently has the tenant, SKU, admin policies... this workshop assumes" confirms even the *builder* hasn't verified this is actionable yet.

**The exercises themselves feel real, not contrived.** Drafting a client letter from a messy legacy doc, tracing deck numbers back to spreadsheet cells, catching planted errors in a portfolio summary, writing recap action items from a meeting transcript — these are exactly things I'd do at my job, using my actual apps. Good fit.

**Module arc pacing is reasonable for AI-new (not just workshop-new) learners.** Module 01 (grounded vs. ungrounded, chat-vs-agent) is a gentle, comparison-based start before Module 02 asks me to hunt for errors and defend corrections — appropriately sequenced, not thrown in the deep end.

**Minor:** README still says "Work IQ" — the design doc (§4) explicitly bans that term as learner-facing, so if this scaffold prose ever leaks through, it contradicts the doc's own terminology rule.
