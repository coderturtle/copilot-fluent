# Mock Learner Gremlin dogfood run - Module 06, 2026-09-14

*Simulation only. All three attempts below are agent-produced role-play, not a real human
learner's work. This run tests whether Module 06's gate mechanism holds up against a genuinely
blind attempt, including a deliberately flawed one - it does not, and cannot, prove anything
about a real human's experience with this module. See
`~/hekton/gremlins/coaching/mock-learner-gremlin.md` (v0.1) for the Gremlin this run dogfoods.*

## What this run is

The second real run of the Mock Learner Gremlin, and the first using the revised roster from
Module 02's own finding (that a personality-only "rushed" persona doesn't reliably produce a
failing attempt): a **diligent persona** (Priya, reused from the Module 02 run for continuity)
and a **scripted-flaw persona** (Marcus, briefed with exactly one concrete, isolated mistake -
misreading Q3's return column as Q4's when picking Molly Jensen's best-performing fund - rather
than a personality trait).

Module 06 has no hidden key (unlike Module 02) - its fixture is fully open to the learner from
the start, and its gate is a self-attested checklist (Tier 1) plus an AI-graded pass on critical
use and tone (Tier 2). Both personas were given the module's full public README (no reveal to
truncate - this module has no inline "don't read ahead" gate) and the fixture's two tables, plus
the same realistic "Analyst agent" first response (reused unmodified from this module's own
existing dry run, `runs/2026-09-13-module-06-dry-run/analyst-initial-output.md`, to isolate what
this run actually tests: not whether an agent can invent a plausible Analyst output, but whether
a blind learner correctly reviews a given one and builds a compliant deck from it).

## The finding: the scripted flaw exposed a real gap in the Tier-1 checklist, and the Tier-2 pass closed it

Marcus's mistake was exactly as scripted: an honest, isolated misread (Castle Income Fund's Q3
return, +0.7%, mistaken for a Q4 comparison), cascading correctly into the allocation figure. His
own self-check, run against the checklist's literal wording, returned a false PASS - and this is
not a self-check-effort problem, it's a checklist-wording gap. The checklist's own text says a
figure must "trace to an exact row" and that the learner's own Row ID mapping "confirms an exact
character-for-character match, not an approximation." Row R7 *is* a real row, and it *does* match
character-for-character. Nothing in the checklist's literal wording asks the learner to confirm
the row is the *correct* row for the question actually being asked (the Q4 comparison, not any
quarter's). An honest learner following the checklist exactly as written could reach - and in
this run did reach - the same false PASS Marcus reached.

The independent Verification Agent (given the real ground truth directly, not just the
checklist's own wording) caught it immediately. More importantly, so did the module's own real,
unmodified Tier-2 AI-graded pass, run for real against the exact grading prompt text from the
README (not a paraphrase): it correctly flagged Slide 2's line 3 as introducing "a factual error
the initial output did not have," correctly cited the real Q4 figures (Kellerman +5.1%, R4),
correctly identified that +0.7% is Castle's Q3 figure rather than a Q4 one, and correctly failed
the critical-use-evidence part of the pass while separately, correctly passing the
recommendation-drift part (nothing in the deck's actual text is recommendation-flavored - the
scripted flaw was isolated to the factual error, exactly as intended).

**This is the same shape as Coachgremlin's own two-tier grading finding** (`borrow-native`,
2026-07-05: a naive attempt passed the deterministic tier cleanly; only the conceptual tier
caught it). Here, the self-attested Tier 1 checklist passed a genuinely wrong attempt cleanly;
only the AI-graded Tier 2 pass caught it. The two-tier design is not decorative for this module -
it's load-bearing, and this run is the first real evidence of that for Module 06 specifically
(the module's own dry run tested the AI-grading criteria by hand-reasoning against a hand-built
near-miss deck; this run tests the same mechanism against a genuinely blind attempt and an
unmodified copy of the real grading prompt, and gets the same result independently).

## Recommendation (report-only - not applied in this PR)

Per this Gremlin's own Human Gate ("never edits the module it tests and never decides what to
fix"), this is a finding for a human or a future content-authoring pass to act on, not a change
made here. Concretely: Module 06's self-check checklist item on row-tracing should be tightened
from "traces to an exact row... confirms an exact character-for-character match" to something
that also requires confirming the row is the *correct* row for the specific question asked (right
quarter, right comparison winner), not merely *a* row that matches some text in the deck. Logged
as a new item in `docs/next-actions.md`.

This does not mean the checklist is broken as a design - the two-tier model's whole premise is
that Tier 1 doesn't have to catch everything Tier 2 catches. But a Tier-1 item whose own wording
cannot in principle catch a real, plausible class of honest mistake (a quarter mis-scan on a
dense table) is worth tightening anyway, since Tier 1 is the tier a learner checks *before*
spending the effort of running Tier 2 - a tighter Tier 1 catches this specific mistake earlier
and cheaper, even though Tier 2 already catches it as a backstop.

## What this run does and doesn't prove

- **Proves:** a genuinely blind diligent attempt, given only the module's public content and a
  realistic Analyst first-pass, produces a fully correct deck.
- **Proves:** a genuinely blind attempt with one isolated, realistic mistake produces a
  self-check false positive under the checklist's current wording.
- **Proves:** the module's real, unmodified Tier-2 AI-graded pass catches that same mistake
  independently and correctly, including correctly not over-flagging the (unrelated,
  intentionally clean) recommendation-drift dimension.
- **Does not prove:** anything about a real human's actual experience misreading this table, or
  whether this specific mis-scan is the most likely real-world mistake for this exercise (it was
  chosen as one plausible, concrete, scriptable error among several named in the module's own
  text, not derived from any real learner data).
- **Does not prove:** that every other checklist item in this or other modules has a similar
  exact-vs-relevant gap - this run tested one item, not the whole checklist.

## Friction log

Neither persona reported confusion about what to produce or where to find the fixture data.
Priya's process notes were clean throughout. Marcus's attempt (playing the scripted mistake) did
not report any friction either, since the mistake was scripted to be an undetected, sincere
misread rather than a moment of genuine confusion - by design, this run's friction signal comes
from the grading mechanism's own gap, not from learner-facing confusion.

## Methodological note

This run also validated a technique from the Gremlin's own revised design: reusing a module's
already-authored dry-run artifact (the Analyst initial-output construction) as a shared input to
a blind Attempt Agent, rather than having the Attempt Agent invent its own stand-in. This isolates
what the run is actually testing (does a blind learner correctly review and build from a given,
realistic AI first-pass) from a separate and less relevant question (can an agent invent a
plausible AI first-pass), and is worth carrying forward as a default technique for modules with an
existing dry-run construction to reuse, rather than reinventing new stand-in inputs for every run.

## Cost, observed

Two Attempt Agent runs (~55-82s, ~31k tokens each), two independent Verification Agent runs

agent turns, roughly 150k tokens total, no self-check follow-up turn needed since this module has
no inline reveal to withhold and re-show (unlike Module 02).
