# Mock Learner Gremlin dogfood run - Module 07, 2026-09-14

*Simulation only. Kellerman & Castle is a fictional firm; Molly Jensen, Johnny Castle, Baby Houseman, and Ethan are fictional people invented for this workshop exercise. Nothing in this report describes a real client, a real transcript author, or real financial, legal, or accounting guidance.*

## What this run is

The third real run of the Mock Learner Gremlin, and the first against Module 07: Meetings and Pages in Teams (copilot-fluent). Same two-persona design as the Module 06 run: Priya (diligent — reads the whole transcript carefully, makes no unforced errors) and Marcus (scripted flaw — otherwise diligent, but carries one deliberately injected mistake). Both personas independently drafted a recap of the same fictional Q3-portfolio-review transcript, ran the module's own self-check step on their own submission, and then had that submission independently re-graded by a separate verification pass, without seeing the other persona's work.

The scripted flaw for this run: on action item 1, write "Johnny will get Molly a paper copy of the **Q3** account statement" instead of "...Q2 account statement..." — every other element of the sentence (owner, action, recipient, date) correct. The trap is that the meeting is billed throughout as a "Q3 portfolio review," so a learner anchoring on the meeting's own title rather than Johnny's specific qualifying line ("So this is your Q2 statement — Q3 doesn't close out for a few more weeks yet") lands on the wrong quarter while getting every other word right. The module's own hidden key notes this is a real trap an earlier draft of the module itself fell into.

## The finding: two different failure modes, and a real disagreement about what "exact match" means

The scripted flaw did what it was designed to do. Marcus's self-check caught the Q2/Q3 substitution without being prompted — it re-read Johnny's specific qualifying line, recognized the meeting-title anchor as the source of the error, and called it "a real, embarrassing miss." Independent verification confirmed the same failure, for the same reason, and the two assessments matched almost exactly on all five items (both found only item 2 as a clean exact match). That's a clean, unambiguous success case for the self-check step: a subtle, single-word factual substitution, surrounded by four otherwise-correct sentence elements, was caught by the learner's own honest re-check and corroborated by independent grading.

What this run did not expect to find is the split on Priya's submission. Priya wrote all five required commitments as bolded-name-plus-direct-quote bullets ("**Johnny Castle** — 'I'll get Molly a paper copy of the Q2 account statement by Friday, September 11th.'") rather than as flat third-person sentences ("Johnny will get Molly a paper copy of the Q2 account statement..."). Her self-check applied a strict literal-string standard — is the exact required sentence, as a single contiguous string, present in my document? — and failed all five items on that basis, since "I'll" is not "Johnny will," character for character. Independent verification, grading the same document, treated the bolded name and the quoted commitment as jointly satisfying "owner as literal first word" and "exact substring," and passed all five, flagging the format choice only as a stylistic risk if the real checker turns out to be stricter.

Both graders were being reasonable under different readings of an underspecified rule. Neither the module materials nor this run's instructions state whether the five checked sentences must appear as one contiguous "Owner will verb..." string, or whether an equivalent owner-attribution-plus-quote structure counts. That ambiguity, not learner error, is what produced a diligent, fully-correct submission failing its own self-check while passing independent review — the opposite direction of miscalibration from what the scripted-flaw design is built to catch (a real error slipping past a check), and arguably a more concerning one for a self-check step whose whole purpose is to be trustworthy feedback a learner can act on alone.

## Recommendation (report-only — not applied in this PR)

Two specific, narrow wording changes to the module's self-check README, both targeting things this run actually observed rather than hypothetical gaps:

1. **State the exact-match rule concretely.** Add a line such as: "The 5 checked sentences must appear as a single contiguous phrase reading 'Owner will [action] by [date]' — a first-person quote with the owner's name attached separately (e.g., '**Johnny Castle** — "I\'ll get..."') does not count as a match, even though the underlying commitment is correct. If you used quotes from the transcript, rewrite each of the 5 required lines in the third-person 'Owner will...' form before checking." This would have caught Priya's format issue during self-check without her having to guess at the actual grading rule from a mismatch she couldn't fully explain.
2. **Add an explicit quarter/label-anchoring warning**, given the module's own key already documents this as a real trap an earlier draft fell into: "When an action item references a specific quarter, statement, or label mentioned elsewhere in the meeting (e.g., in the call title), re-read the speaker's specific line rather than assuming the meeting's overall label — meeting titles and framing (like 'Q3 portfolio review') can refer to when the discussion happens, not what's being discussed." This directly targets the mechanism of the scripted flaw, not just its symptom.

## What this run does and doesn't prove

- **Proves:** For this specific scripted flaw (a single mislabeled quarter, everything else in the sentence correct), a careful self-check step caught it, and independent verification agreed — a genuine success for the self-check tier of the two-tier design on this exact failure mode.
- **Proves:** The module's exact-match checking rule, as currently documented, is ambiguous enough that two good-faith graders (a self-check and an independent verification pass) reached opposite verdicts on the same fully-correct submission, differing only on sentence format.
- **Does not prove:** What the module's actual automated checker (if one exists, as opposed to a human or LLM grader) actually implements — this run surfaces the ambiguity, it doesn't resolve which reading is correct. That would require inspecting the real checker logic, which was out of scope here.
- **Does not prove:** That real (non-scripted, non-simulated) learners would reproduce either persona's behavior — one scripted transcript, one flaw, one run per persona is not a distribution over learner behavior, and both "personas" are simulated reasoning, not actual human learners under time pressure.
- **Does not prove:** Anything about Part 2 of the module (Copilot Pages) or the AI-graded clarity pass — Priya's submission never attempted either, and this run did not separately exercise them, so the report is silent on that half of the module's checklist coverage.
- **Does not prove:** That the quarter-anchoring trap would be caught as reliably under different phrasing of the same scripted flaw (e.g., a label embedded in a different part of the transcript, or a flaw with no easy landmark like a title to anchor on).
