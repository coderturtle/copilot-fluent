# Mock Learner Gremlin dogfood run - Module 01, 2026-09-14

*Simulation only. Both personas are roleplayed by Claude in a single session; no live Microsoft 365 Copilot session was available in this dogfood environment, and both personas' "AI-graded pass" for the app-comparison notes is a self-authored transcript, not a real model call. This is flagged explicitly in the findings below because it bears directly on what this run can and can't prove.*

## What this run is

The third real run of the Mock Learner Gremlin against a copilot-fluent workshop module, and the first against **Module 01: Starting at Kellerman & Castle**. As before, two personas attempt the module independently, each runs its own self-check against the revealed checklist, and each then gets an independent-verification pass graded against the module's stated ground truth. Priya (diligent) does the module honestly and correctly throughout. Marcus (scripted flaw) does Parts 1 and 2 correctly but is scripted to fail the third checklist item — the app-comparison notes required for the module's AI-graded pass — with two notes that read as two distinct, on-topic differences but are actually both generic domain restatements ("good with numbers" vs. "good with writing," "analytical" vs. "conversational") of exactly the kind the module's own grading criterion says not to accept.

## The finding: two different failure modes, and a self-check/independent-verification split

This run surfaced two distinct things worth separating.

**1. The scripted content flaw was caught, on both tiers, for the scripted-flaw persona.** Marcus's submission embedded a self-authored grading transcript that returned "Pass" on the flawed notes — and his own process notes took that Pass at face value ("the grading pass came back with a clear Pass, so I'm treating that as confirmation"), exactly as scripted: the error is sincere and undetected in the original submission. On self-check, re-reading the two notes against the actual grading criterion (not against the submission's own Pass verdict) correctly identified them as generic domain restatements and flipped the verdict to FAIL. Independent verification, working from the module's stated ground truth and explicitly declining to defer to the submission's self-reported Pass, reached the same FAIL for the same reason. Both tiers worked as designed here: neither one was fooled by a flaw that reads, on a shallow "are there two bullet points" check, as clearing the bar.

**2. An unscripted disagreement showed up on the diligent persona's submission, and it's a real one.** Priya's app-comparison notes were genuinely good — concrete, specific capability differences, not restatements. But rather than running them through a live Copilot session (none was available), she wrote a "Simulated grading pass" predicting what Copilot would say. On self-check, she re-read the module's own instructions and concluded this doesn't satisfy the requirement: the module frames the AI-graded pass as one of two concrete required outputs, describes it as having Copilot "apply the grading prompt... and return a verdict I didn't write myself," and carries none of the honor-system caveat that the fact-count checklist items explicitly do. She failed her own submission on those grounds, independent of whether the notes were good. Independent verification, however, was working from a ground-truth spec that defined the item purely as text-matching against the grading criterion's content — and under that spec, "did the notes satisfy the criterion" is a yes, so it passed the item, noting the self-grading-instead-of-real-grading issue only as a caveat rather than grounds for failure.

That's a genuine split between the two tiers on the same submission, driven not by a grading mistake but by a difference in what each tier was checking: self-check was reading the module's *procedural* requirement (get an actual AI-graded pass), independent verification was reading a *content* ground truth (do the notes pass the stated criterion). Both readings are defensible given what each grader had in front of it — which is itself the finding. If the deployed module's ground-truth document for independent verification doesn't carry the same "this must be a real AI pass, not a self-graded one" requirement that the module's own learner-facing text does, the two tiers will disagree on exactly this kind of submission in production, not just in this dogfood run.

## Recommendation (report-only — not applied in this PR)

1. Align the independent-verification ground truth for Module 01's AI-graded-pass item with the module's own learner-facing language: it should explicitly state that a self-authored/predicted grading transcript does not satisfy the requirement, mirroring the honor-system caveat the module already attaches to the fact-count checklist items but pointedly omits here. Right now the two tiers can legitimately disagree, as they did in this run.
2. Consider having the module's checklist instruct learners with no live Copilot access (which, per this run, appears to be the actual dogfood-environment default rather than an edge case) to label a simulated grading transcript as such explicitly, rather than leaving disclosure to individual judgment — Priya disclosed it prominently and un-trusted her own result; Marcus (scripted, but plausibly representative of an honest learner who didn't think to flag it) didn't disclose it and trusted it. The module can't rely on learners consistently self-flagging this on their own.
3. No change is recommended to the app-comparison grading criterion's wording itself — it already names "Copilot is good with numbers / good with writing" and "analytical / conversational" as explicit failing examples, and both graders in this run correctly matched Marcus's notes against those named examples without needing to infer the pattern.

## What this run does and doesn't prove

- **Proves:** the scripted content flaw (two generic-restatement notes dressed as two real differences) was correctly caught by both self-check and independent verification for the scripted-flaw persona, and the diligent persona's genuinely correct Part 1 and Part 2 work was correctly passed by both tiers with no false negatives on fact-counting or the four-scenario sort.
- **Proves:** the two-tier design can produce a live disagreement (FAIL vs. PASS) on the same real submission when the module's procedural requirements and the independent-verification ground truth aren't worded identically — this wasn't a hypothetical risk, it happened in this run, on the diligent persona's submission, over whether a self-graded prediction satisfies "get an AI-graded pass."
- **Does not prove:** that a real, live Copilot session would reject the flawed app-comparison notes when actually given the module's grading prompt. No persona in this run had live Copilot access; both "AI grading passes," including the one that returned an incorrect Pass, are self-authored simulations. The module's actual integrity mechanism — a real model applying the real grading prompt — was never exercised here.
- **Does not prove:** anything about learner behavior at scale. Two personas, one run each, against one module.
- **Does not prove:** whether the self-check/independent-verification split on Priya's submission reflects an actual gap in the deployed ground-truth document, since this run's "independent verification" ground truth was supplied inline for this exercise rather than read from the module's real spec file.

## Friction log

Both personas independently reported no live Copilot access in this exercise environment and had to write simulated transcripts for all three checklist items, not just the app-comparison one. Priya treated this as a live source of doubt and it drove her self-check FAIL; Marcus's persona did not flag it (consistent with the scripted flaw, since surfacing it would have tipped off the plant, but also plausibly realistic — an honest learner in a no-access environment might not think to distrust their own simulated grading pass the way Priya did). The asymmetry between "no live tool access" being flagged as insufficient for one checklist item (the AI-graded pass) but implicitly accepted for another (the Part 1 transcripts, which carry an explicit honor-system caveat in the module) is itself a piece of friction worth the module authors seeing — it's not obvious to a learner why one simulated step is explicitly tolerated and the other isn't, unless they read the module text as closely as Priya did.
