## What this run is

The next real run of the Mock Learner Gremlin, this time against Module 04: Conversations, Notebooks, and Memory. As before, two personas independently work the same exercise: Priya (diligent, no scripted errors) and Marcus (scripted flaw). Both personas produce an in-character submission, then an in-character self-check against the revealed answer key, then an independently-run verification pass — three separate looks at the same work, same as the Module 06 run.

The scripted flaw this run targets Part 5's true/false quiz on memory vs. custom instructions. Marcus is scripted to correctly recall a real, module-sourced fact — "chat-history-derived details clear within 7 days of deleting every chat that mentioned them" — and then misapply it to the wrong mechanism: Statement 4 is about *saved memories*, whose lifecycle is independent of any single deleted chat (they only clear on direct user deletion), not about the separate Chat History inference control the 7-day window actually governs. This produces a plausible-sounding wrong answer built on a real citation, which is the specific failure mode a shallow self-check ("did you cite real terminology from the doc?") would not catch.

## The finding: value-vs-key comparison caught the scripted flaw; surface checks would not have

On Marcus's submission, both the self-check and the independent verification pass caught Statement 4, and both did it the same way: by diffing Marcus's stated TRUE/FALSE value against the published key, not by evaluating whether his reasoning *sounded* grounded in the material. That distinction matters because Marcus's citation is genuine — "chat-history-derived details clear within 7 days" is a real fact from the module — so a self-check that only asked "did the learner reference real terminology/detail from the doc?" would have passed this answer. It's only checking the actual boolean against the key that surfaces the conflation. Both graders in this run did exactly that, and both named the correct root cause (mixing up the Chat History inference control with the separate saved-memories mechanism) rather than just marking it wrong.

This is one data point in Marcus's favor for the two-tier design: self-check plus independent verification both caught a "real citation, wrong application" error, which is a harder case than a fabricated fact would be. It does not establish that self-check will always drill to value-level comparison rather than being satisfied by surface signals — this checklist item happened to be phrased as "do the four answers match the key exactly," which makes the value-diff close to unavoidable. A checklist item phrased more like "did you use real details from the material" would be a meaningfully different (and weaker) test, and this run says nothing about that version.

**Correction, made before publishing this report, not by either persona or grader:** both personas independently ended their submissions after Part 5's quiz and never produced the required Part 6 ("write your own personal instructions") section. The raw run treated this as an unscripted, "suspicious" two-for-two learner gap worth flagging as ambiguous. It isn't ambiguous — checked directly against this module's real `README.md`, the design stage's own assembled `publicContent` for this run ends exactly at the end of Part 5's four statements and never contained Part 6 at all (confirmed by diffing the run's input against the file on disk). Neither persona skipped anything; neither was ever given it. This is a Mock Learner Gremlin pipeline defect — a content-assembly gap in this run's automated setup, not a finding about Module 04, and not evidence about learner behavior at Part 6. It has been fed back into the Gremlin's own definition (see the hekton companion PR) as a new Risk, not reported here as a module finding. Parts 1-5's results above are unaffected and stand as recorded; Part 6 is simply untested this run.

## Recommendation (report-only — not applied in this PR)

1. Where a checklist item is meant to catch a "real fact, wrong mechanism" error like this one, keep the wording as a direct value-vs-key diff ("does the learner's stated answer for statement N match the key exactly") rather than a citation-presence check ("did the learner reference real material"). This run suggests the former catches genuine-but-misapplied citations; the latter would not have, since Marcus's citation was authentic.
2. No recommendation follows for Part 6 from this run — it was never tested, per the correction above, not because it revealed nothing.

## What this run does and doesn't prove

- **Proves:** In this run, on this one scripted flaw, a self-check and an independent verification pass that both did direct value-by-value comparison against the revealed key caught a wrong answer built on a real, correctly-recalled citation that was misapplied to the wrong mechanism — and both correctly identified *why* it was wrong, not just *that* it was wrong.
- **Does not prove:** That self-check will reliably do value-level comparison rather than accepting surface plausibility in general — this checklist item's wording made that comparison nearly unavoidable, and this run doesn't test a more loosely-worded item. Does not prove anything about Part 6 at all — it was never included in what either persona received, a run defect caught and corrected before publishing, not a module or learner finding. Does not independently audit Parts 1–4's procedural claims (exact title strings, notebook membership, deletion) beyond self-report, consistent with the module's own acknowledged trust limitation on that section.
