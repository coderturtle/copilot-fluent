# Mock Learner Gremlin dogfood run - Module 09, 2026-09-14

*Simulation only. Both attempts below are agent-produced role-play, not a real human learner's
work. This run tests whether the capstone's gate mechanism holds up against a genuinely blind
attempt, including deliberately flawed ones - it does not, and cannot, prove anything about a real
human's experience. See `~/hekton/gremlins/coaching/mock-learner-gremlin.md` (v0.1) for the
Gremlin this run dogfoods.*

## What this run is

The third real run, scoped to 4 of Module 09's 8 parts - the fact-bound, mechanically-checkable
ones (Part 2: verification memo, Part 5: word-bound summary, Part 6: traceable deck, Part 7:
recap) - skipping the four parts the module's own text already admits can't be mechanically
checked (Parts 1, 3, 4, 8). Two personas: diligent (Priya, reused across all three runs so far)
and scripted-flaw (Marcus, briefed with **three** distinct, isolated mistakes this time, one per
part, chosen to probe the capstone's own named distinguishing risk - cross-module/cross-quarter
fact contamination - rather than repeating Module 06's single-mistake shape):

- **Part 5:** mistakes the AUM figure ($794,300) for "the note's own top-line figure," when the
  note's opening sentence explicitly flags a different figure (the 18.4% cumulative return) as
  the one "worth leading with."
- **Part 6:** correctly picks the right best-performing fund, but reports a stale allocation
  figure (92%/0%/8%, an earlier quarter's rebalancing for the same fund) instead of this
  quarter's real one (89%/3%/8%), while still citing the real row ID (Q27-A1) as the source -
  a citation that doesn't match its own row's actual content.
- **Part 7:** lists Molly's "get more organized" remark - an explicit decoy the transcript itself
  disclaims ("that's a me problem, not a today problem") - as a third action item.

genuinely blind, careful attempt.

## The three findings, and a genuine limit on what this run proves about them

**Part 5** - mechanical checks (word count, transplant count, keyword presence) all pass on
Marcus's summary even though it contains a false claim. The 18.4% figure is present in the text -
the summary just also *mislabels a different figure* as the important one. A presence check can't
catch a false editorial claim sitting next to a technically-satisfied requirement.

**Part 6** - the citation "traces to an exact row" (Q27-A1 is cited, and it's a real row), but the
figures written next to that citation don't match what that row actually contains. This is a
sharper version of Module 06's earlier finding: there, the wrong row was at least internally
consistent with itself; here, the citation and the content it's attached to actively disagree,
which should be more mechanically catchable (a literal diff against the row's real text) than
Module 06's quarter-mixup was.

**Part 7** - the checklist explicitly, in its own real wording, warns against exactly this trap
("doesn't list Molly's open-ended remark as if it were one"). This is the cleanest test of the
three, since it directly checks whether an explicit, already-written warning actually works when a
learner is honestly trying to follow it.

**Marcus's own self-check caught all three, matching independent verification exactly - but this
run cannot cleanly credit that to the checklist wording alone**, and saying so is the more
important finding here than the three individual defects. Unlike Module 06's self-check (produced
in the same single turn as the attempt itself, with no additional prompting), this run's self-check
came from a follow-up turn in which the reveal message explicitly instructed Marcus to "actually
re-verify... don't just restate" and, for Parts 5 and 6 specifically, to re-read the source
sentence and re-check against the current fixture table rather than memory. That instruction goes
beyond Part 5 and Part 6's own literal checklist wording (which requires the *result* of a correct
check, not a specific verification procedure) - Part 7's catch is the one clean result, since its
warning is genuinely already in the module's own text. For Parts 5 and 6, this run shows that
**an explicitly-prompted "go back to the source, don't trust your own draft" self-check catches
these errors** - a real and useful finding - but it does not show that the checklist's *current*
wording alone, read and applied without that extra nudge, would do the same. That's a materially
different, weaker claim than "the checklist works," and conflating the two would overstate this
run's evidence.

## Recommendation (report-only - not applied in this PR)

Two distinct recommendations follow, correctly scoped to what this run actually shows:

1. **For Module 09 specifically:** Part 5's and Part 6's checklist items could be tightened the
   same way Module 06's was (see `docs/mock-learner-runs/2026-09-14-module-06.md`) - naming the
   specific re-verification action, not just the required end state. Logged in `docs/next-actions.md`.
2. **For this Gremlin's own methodology, more importantly:** the self-check reveal turn's own
   prompt needs to be standardized and used identically across runs, not written fresh (and with
   varying amounts of implicit scaffolding) each time - otherwise a "the self-check caught it" vs
   "the self-check missed it" comparison between two runs is comparing two different experiments,
   not the same checklist under the same conditions. Fed into the Gremlin's own definition (see
   below) rather than left as a one-off observation.

## What this run does and doesn't prove

- **Proves:** a genuinely blind diligent attempt handles this quarter's new, unfamiliar facts
  correctly across all four tested parts, including two traps specifically designed to catch
  cross-quarter/cross-module fact confusion - real evidence the capstone's synthesis premise holds
  up against an attempt that hasn't seen these figures before.
- **Proves:** three distinct, realistic scripted mistakes (a mislabeled "important figure," a
  stale-but-cited allocation figure, an over-inclusive decoy) are all independently verifiable as
  wrong against the real fixtures, and none is caught by presence/citation-existence checks alone.
- **Proves, with the scaffolding caveat above:** an explicitly-prompted, source-re-checking
  self-check catches all three when given that instruction.
- **Does not prove:** that the checklist's own current wording, applied by a learner without that
  extra prompting, would catch Parts 5 and 6's errors - that's a distinct, weaker, still-open
  question this run's own design didn't cleanly separate from the "does an explicit reveal-turn
  nudge help" question.
- **Does not prove:** anything about the four untested parts (1, 3, 4, 8) of this same module.
