# Mock Learner Gremlin dogfood run - Module 08, 2026-09-14

*Simulation only. All three attempts below are agent-produced role-play, not a real human learner's
work, and — new to this run, named up front rather than discovered partway through — neither persona
had actual Microsoft 365 Copilot access to drive. This run tests whether Module 08's gate mechanism
holds up against a genuinely blind attempt, including a deliberately flawed one; it does not, and
cannot, prove anything about a real human's experience with this module. See
`~/hekton/gremlins/coaching/mock-learner-gremlin.md` (v0.1) for the Gremlin this run dogfoods.*

## What this run is

The fourth real run of the Mock Learner Gremlin, and the first against a module whose artifact isn't a
spreadsheet-grounded memo or deck (Modules 02, 06, 09) but a live external SaaS UI — Microsoft 365
Copilot's Agent Builder. Same roster as Runs 2-3: a **diligent persona** (Priya, reused for
continuity) and a **scripted-flaw persona** (Marcus, briefed with one concrete, isolated mistake).
The flaw this run targets a dimension none of Runs 1-3 tested: not citation-exactness or fact-tracing,
but Part C's recommendation-language hand-read. Marcus was briefed to write his own Part B Instructions
text (the README explicitly allows the worked example "as-is or as a starting point," so customizing it
is a realistic, non-lazy choice) and, alongside all the correct core restrictions, add one extra clause:
"...and flag any of the client's accounts that might need extra attention before the meeting." This
clause uses none of the vocabulary Part C tells the learner to watch for (no "recommend," "buy," "sell,"
"invest," "tax") but is a real scope violation: it asks the agent to make a suitability-flavored judgment
about a specific client's specific accounts, which Part C's own wording rules out ("nothing that judges
whether something suits a particular person's situation") and which the fixture's own "What this playbook
is not" section separately rules out ("nothing in it says or implies what any client should do with their
own money"). It also contradicts the fixture's explicit Household Snapshot rule ("current values only,
**no commentary**").

Both personas were given the module README and the playbook fixture only. Neither reported, nor was
given, a live Microsoft 365 Copilot session to click through — Priya disclosed this openly in her
process notes; Marcus's submission does not disclose it and instead reads as though a real agent was
built, tested on the Try It tab, and shared. Whether that asymmetry reflects a real difference in what
each persona had access to, or just a difference in what each chose to say, this run's evidence can't
distinguish — and that turned out to be a second, unplanned finding in its own right (below).

## The finding: the scripted flaw survived a literal Part C hand-read, and independent verification caught it

Marcus's mistake worked exactly as scripted. His own Part C read went instructions-then-prompt,
one at a time, against a mental checklist of banned terms — no "recommend," no "tax," no "buy/sell," no
client-facing-drafting invitation — and the added clause tripped none of them, so he wrote "I didn't find
any of that" and moved on. His own self-check, re-reading the same clause against the *actual named
standard* ("nothing that judges whether something suits a particular person's situation") rather than a
keyword list, caught it on the second pass: "flag any of the client's accounts that might need extra
attention" is a suitability judgment about specific client accounts, not a banned word. Independent
verification confirmed the same reading independently, and additionally traced the contradiction with the
fixture's own Household Snapshot rule ("no commentary") that neither the attempt nor the first self-check
pass had connected. This is the same shape Runs 2 and 3 already established for other modules — a
presence/keyword-style check clears a genuinely wrong attempt, and only a check against the actual named
rule (not the rule's most obviously-flagged vocabulary) catches it — now confirmed for Part C's
recommendation-language hand-read specifically, a dimension Runs 1-3 never exercised.

**One qualifier worth stating plainly:** Marcus's own OOC note is honest that this was scripted to survive
exactly this kind of check, so finding that it did is closer to confirming the script worked than to an
independent discovery. What is independent evidence is that the *self-check*, given a second, more
literal instruction to check against the standard's actual wording, caught what the first pass missed —
that gap between a keyword scan and a standard-wording check is real and reproducible, not scripted.

## The more consequential finding is about this Gremlin's own method, not about Module 08

Priya's self-check failed this run's gate for a completely different, structural reason: no live
Microsoft 365 Copilot session was available to build, share, query, or transcript against, so Part B, Part
D, and Part E's evidentiary requirements (a real agent, a real share, real transcripts) could not be met —
only described. Priya disclosed this openly and her own self-check correctly failed the gate on those
grounds, confirmed by independent verification. Marcus's submission shows no equivalent disclosure and
instead states Part D happened ("shared... no admin block hit") and presents Part E's transcripts without
qualification; neither his self-check nor the independent verification pass flagged this, because nothing
in his write-up signaled there was anything to flag. This run cannot tell whether that's because Marcus's
persona genuinely had access Priya's didn't (unlikely, since both are agent role-play against the same
module text with no live tooling connected in this run) or simply because he didn't say so — but either
way, it demonstrates a real gap: **this module's required gate depends on evidence (a real build, a real
share, real transcripts) that a written submission cannot be independently checked for, and a learner who
discloses the gap honestly is the one who gets caught by it, while a learner who is silent about the same
gap is not.** That is not a flaw in either persona's honesty; it is a limit on what this Gremlin, run this
way, against a module of this shape, can actually verify. Modules 02/06/09's gates all reduce to a text
artifact (a memo, a deck, a summary) the Attempt Agent can genuinely produce and be graded on blind —
Module 08's gate does not reduce that way, and this run is the first time that mismatch showed up.

## Recommendation (report-only — not applied in this PR)

Two distinct recommendations, scoped to what actually failed:

1. **For Module 08's Part C / Required Gate checklist specifically:** the recommendation-language rule
   is currently stated only in the general form ("nothing that judges whether something suits a
   particular person's situation"), with no worked negative example the way Module 09's Part 7 already
   names its own decoy trap in the checklist's own text ("doesn't list Molly's open-ended remark as if it
   were one"). Run 3's own evidence is that an explicit, already-written warning is the most reliably
   caught trap of the ones tested so far. Adding one concrete worked example of subtle-drift phrasing that
   avoids named banned vocabulary (something in the shape of "flag accounts that might need extra
   attention" is a plausible choice, since it's realistic and exactly the kind of clause a well-meaning
   learner customizing the worked instructions might add) would give Part C's hand-read something concrete
   to pattern-match against, not just a general rule to apply cold.
2. **For this Gremlin's own definition, more importantly:** `mock-learner-gremlin.md`'s Risks section
   should name, as a new and now-confirmed risk, that modules whose required gate depends on operating a
   live external SaaS tool (rather than producing a checkable text artifact) cannot currently be tested
   the way Modules 02/06/09 were — the Attempt Agent has no way to actually build, share, or query a real
   Microsoft 365 Copilot agent, so any run against such a module either needs to scope itself explicitly
   to the text-reducible parts only (Part A's reasoning, Part C's hand-read, the AI-graded pass's input
   text — the same kind of explicit scoping Run 3 applied to Module 09's 4 of 8 parts), or needs to wait
   for an Attempt Agent with real browser-driving capability. Running it unscoped, as this run did,
   produces a confusing result where both personas "fail" for reasons of very different severity and
   informativeness, muddying the signal the scripted-flaw comparison was actually designed to produce.

## What this run does and doesn't prove

- **Proves:** a scripted, realistic, keyword-avoiding suitability-judgment clause survives a literal,
  good-faith Part C hand-read performed against a mental list of banned words rather than the rule's
  actual wording — the same checklist-wording gap shape Runs 2 and 3 found in different modules, now
  confirmed for the recommendation-language dimension specifically.
- **Proves:** a self-check re-run against the standard's actual wording (rather than a keyword scan)
  catches the same clause the first pass missed, and independent verification agrees — evidence the gap
  is in how the check is performed, not that the standard itself is unstatable.
- **Proves, as an unplanned but real finding:** this Gremlin, run without live Microsoft 365 Copilot
  access, cannot verify Module 08's build/share/transcript requirements at all — only a submission's own
  honesty about that gap is currently what surfaces it, and this run shows that honesty is not something
  the pipeline can independently confirm or penalize consistently between two personas.
- **Does not prove:** that a real learner with genuine Microsoft 365 Copilot access would make the same
  Part C mistake, or would catch it the same way on a second pass — this run's personas worked from module
  text and a self-authored mockup, one extra remove from the module's real intended workflow compared to
  Runs 1-3, and that degradation should be named plainly rather than glossed over.
- **Does not prove:** what the module's own real AI-graded pass would say if the flawed config block were
  actually pasted into a live Copilot session — Marcus's OOC note asserts it would likely be caught, but
  unlike Run 2's real Tier-2 execution or Run 3's real self-check reveal turn, this run never actually ran
  a real grading pass against real product output.
- **Does not prove** anything about Modules 02/06/09's already-reported findings, which remain unaffected
  by this run's different failure mode.

## Methodological note

This run's design differs from Runs 1-3 in a way worth stating plainly rather than discovering by
inference: Modules 02, 06, and 09 gave the Attempt Agent a real fixture and asked it to produce a real,
checkable text artifact (a memo, a deck, a summary) end to end, blind. This run instead asked both
personas to describe what they would configure in a UI neither could actually drive, which is a
meaningfully weaker test of the same gate — not because either persona reasoned poorly, but because
the module's own required evidence (a real build, a real share, real transcripts) isn't the kind of
thing a description can stand in for, a distinction Priya's own self-check drew correctly and Marcus's
did not draw at all. Future runs against a module of this shape should either scope down to the
text-reducible parts explicitly (per the recommendation above) or hold off until this Gremlin has a way
to actually operate a live external tool.
